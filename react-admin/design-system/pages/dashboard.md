# 运维概览

## 页面定位

`/dashboard` 是单个 Edge Collector 部署实例的只读运维概览。页面首要回答两个问题：当前运行是否正常、出现问题后应该进入哪个已有页面排查。

页面不承担项目切换、多实例聚合、直接控制、配置变更、正式业务告警、历史趋势或工程业务指标展示。

导航和页面标题统一使用“运维概览”，不再使用泛化的“工作台”；“运行总览”保留给 MQTT 页面。

## 数据来源与组合

首版由前端并行调用现有只读接口组合页面，不新增 Dashboard 聚合接口，也不新增历史指标存储：

| 健康分域 / 内容 | 数据来源 | 首页用途 |
| --- | --- | --- |
| 采集通道 | `/api/v1/acquisition/channel-state`，必要时结合通道配置列表 | 通道状态板、状态摘要、关注项 |
| 设备通信 | `/api/v1/acquisition/states` | 设备状态摘要、通道设备数量、关注项 |
| 协议脚本 | `/api/v1/acquisition/script-states` | 识别最近脚本运行失败，作为采集关注项 |
| MQTT 上行 | `/api/v1/mqtt/state`、`/api/v1/mqtt/outbox/stats` | MQTT 状态、Outbox 容量和 pending 信息 |
| 服务 / 数据库 | `/health`、`/ready` | 进程存活与数据库就绪状态 |

每个分域独立处理 loading、成功、错误和过期状态。某个请求失败不得推断另一个分域失败；后续刷新失败时保留最近一次成功数据，并明确标注可能已过期。

Dashboard 需要遵循用户已有的模块权限：无权访问的分域不请求、不展示、不计入当前用户可见的关注项数量。MQTT 分域沿用 `mqtt:overview:list` 权限；其他分域沿用各自页面的访问边界。

## 首屏结构

桌面端采用主区域 + 辅助区域的两栏布局；移动端按纵向顺序排列。

```text
运维概览                                                [刷新] [最近刷新时间]
单个部署实例当前运行状态

┌────────────────────────────────┬─────────────────────┐
│ 运维关注项                     │ 健康分域摘要         │
│ 最多 6 项，严重程度优先         │ 采集运行             │
│ 通道 / 设备 / MQTT / 脚本问题   │ 设备通信             │
│ 无关注项时显示明确的正常空态     │ MQTT 上行            │
│                                │ 服务 / 数据库        │
├────────────────────────────────┴─────────────────────┤
│ 通信通道状态                                           │
│ 状态 · 通道名称 · 协议 · 设备状态摘要 · 最近成功时间    │
│ 关注项置顶，全部已启用通道可滚动查看                    │
└────────────────────────────────────────────────────────┘
```

桌面端建议使用 `8 / 4` 的内容比例：左侧承载关注项和通道状态，右侧承载四个紧凑健康摘要。移动端顺序为：健康分域摘要 → 运维关注项 → 通信通道 → MQTT/服务详情。

不放置趋势图、最近操作、站内通知、用户待办、地图、车辆信息、寄存器值或工程业务指标。

## 健康分域摘要

健康分域必须独立表达，不合成“系统健康率”或单一百分比。

- **采集运行**：通道总数、在线、部分失败、离线；未配置或未启用不伪装为在线。
- **设备通信**：设备总数、在线、等待首次采集、部分失败、离线。
- **MQTT 上行**：runtime 状态、Broker 连接状态、Outbox 利用率；Raw pending 作为信息指标。
- **服务 / 数据库**：分别表达进程存活和数据库就绪，不由此推断采集或 MQTT 正常。

MQTT 状态沿用现有语义：停用为中性，连接中/重连中为警告，错误或断开为关注；Outbox 行数或字节利用率达到 80% 为预警，达到 100% 为严重。`oldestAge` 和最近投递错误只提供上下文，不单独替代容量状态。

## 运维关注项

关注项覆盖以下已有运行来源：

- 服务或数据库数据不可用；
- MQTT 连接错误、Outbox 容量风险；
- 通信通道 `DEGRADED / OFFLINE`；
- 通道正常但设备 `DEGRADED / OFFLINE`；
- 协议脚本最近运行失败。

未配置、等待首次采集和 MQTT 预期停用属于信息状态，不自动计入故障数量。动态事件、登录日志、操作审计日志、站内通知和正式业务告警不直接放入此列表。

关注项按以下顺序排序：

1. 服务 / 数据库数据不可用；
2. MQTT 连接错误或 Outbox 已满；
3. 通信通道离线；
4. 设备离线；
5. 通道或设备部分失败、脚本失败、Outbox 容量预警。

同一层级内按问题持续时间排序，持续时间更长的优先。通道异常时以通道作为层级关注项，并显示受影响设备数量；不在首页重复展开由该通道直接导致的设备离线项。通道正常但单个设备异常时，显示具体设备。

首屏最多显示 6 项，同时保留分类总数和“查看全部”入口。

## 通信通道状态板

状态板展示全部已启用通道，关注项置顶；禁用通道不计入运行健康。通道数量增加时保持全量可查看，首屏区域使用滚动而不是 Dashboard 内分页。

每行至少展示：

- 通道运行状态；
- 通道名称；
- Modbus 传输协议；
- 设备状态摘要；
- 最近成功时间；
- 最近错误信息或错误提示。

通道状态来自当前运行状态，不把原始寄存器值解释成电压、电流、温度等业务实时数据。点击通道或设备进入 `/acquisition/realtime`，并带上对象上下文；实时寄存器页面负责具体值、寄存器块有效性和错误详情。

## 空态、错误态与刷新

- 没有配置通道或设备：显示“尚未配置”，有权限时提供进入通信通道或设备管理的入口。
- 已配置但等待首次采集：显示等待状态，不使用错误色。
- 当前没有关注项：显示明确的“当前没有需要关注的运行问题”。
- 首次请求失败：在对应分域显示错误说明和重试入口。
- 后续刷新失败：保留最近一次成功数据，并显示“数据可能已过期”和最近成功刷新时间。
- 页面可见时约每 10 秒自动刷新；页面不可见时暂停自动刷新，重新可见时立即刷新。
- 始终提供手动刷新。刷新按钮不能因为单个分域失败而阻塞其他分域。

所有时间字段继续使用 `src/lib/datetime.ts`，按 `Asia/Shanghai` 展示；不通过字符串截取或替换模拟时区转换。

## 排查入口

- 通道或设备：`/acquisition/realtime`，预选或筛选对应对象；
- 协议脚本失败：`/acquisition/script`；
- MQTT runtime 或 Outbox：`/mqtt/overview`；
- 服务 / 数据库请求失败：保留当前页错误说明、重试入口和必要的健康检查信息。

Dashboard 不直接启动/停止采集、不发布配置、不下发 MQTT 控制指令。

## 视觉与响应式规则

沿用 `design-system/MASTER.md` 的浅色蓝灰企业后台 token：白色内容面、浅灰背景、蓝色操作色、红/橙状态色。页面的特征来自运行状态信号带和高密度状态板，而不是渐变、插画或大面积装饰。

状态色只表达状态；所有状态同时提供文字，不依赖颜色单独传递含义。数字和计数使用等宽数字，关注项具备键盘焦点、清晰 hover 和可读的错误说明。减少无意义动画，尊重 reduced motion。

移动端摘要卡片单列，关注项和通道状态使用紧凑列表；页面不出现横向溢出，长错误文本允许换行。桌面端通道状态板可在内容区域内滚动，不能把主页面撑出视口。

## 明确不包含

- 项目选择器、多实例聚合、租户或组织数据范围；
- 正式业务告警中心、告警确认/恢复生命周期和告警历史；
- 车辆、位置、地图、CAN 或工程业务指标；
- 历史趋势、可用率、吞吐量和采集量统计；
- Dashboard 专属后端聚合 API；
- Dashboard 内直接控制、配置变更或命令下发。

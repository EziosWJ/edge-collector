# Detail Page 详情页

## 1. 使用场景

适用于业务详情、只读信息、状态摘要、元数据和操作记录展示。

## 2. 不适用场景

需要大量编辑时使用 Standard Form；从列表进入的短只读信息可使用 `DetailDialog`；数据量主要是可筛选表格时使用 Standard List。

## 3. 页面标准结构

```text
PageHeader
├─ 返回 / 编辑等页面操作
├─ 摘要区：标题、编号、状态、关键指标
└─ ContentCard 分组
   └─ label / value 只读信息
```

## 4. 应复用的公共组件

复用 `PageHeader`、`ContentCard`、`DetailItem`、`StatusTag`、`Button` 和必要的状态/空状态组件。详情字段保持统一的 label/value 对齐方式。

## 5. 页面自行负责的业务内容

页面负责详情数据加载、字段格式化、状态映射、权限、编辑/返回操作、关联资源和时间线内容。公共详情组件不获取业务数据。

## 6. Toolbar 与查询区规范

详情页没有列表查询区。页面主操作放在 `PageHeader`；区块级操作靠近对应区块，避免把所有动作堆到页面底部。

## 7. 空状态、Loading、Error

加载中、加载失败和记录不存在需要区分。只读字段缺失显示统一占位符；关键状态和下一步操作不能只依赖颜色表达。

## 8. 响应式要求

摘要区在窄屏下纵向排列；信息分组可从多列降为单列；长文本换行，不能撑破内容区。

## 9. 对应 Demo

`src/pages/examples/detail-demo.tsx`，路由 `/examples/detail`。它展示摘要卡片、状态、基础信息和分组信息。

## 10. 对应真实业务页面

当前真实业务主要通过日志、文件等 `DetailDialog` 展示短详情；个人中心属于详情信息与上传区块的组合。若后续出现独立详情路由，应优先参照本 Demo。

## 11. 使用边界

字段分组和业务状态不同不需要新建详情布局。只有出现明显不同的主任务和信息组织方式时，才记录页面覆盖规则。

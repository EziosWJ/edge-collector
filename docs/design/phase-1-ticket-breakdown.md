# 第一阶段 Ticket 拆分

> 总 Spec：Issue #1
>
> ADR：ADR-0011、ADR-0013、ADR-0014
>
> 技术方案：`docs/design/phase-1-acquisition-technical-design.md`

第一阶段按纵向能力拆分，避免按“数据库 / 后端 / 前端”横向切割成无法独立验收的碎片。

## 实施顺序

1. **#2 采集配置基础**：RS485 通道、设备与寄存器读取块持久化、CRUD、页面配置。
2. **#3 原始寄存器读取契约**：固化 FC03 / FC04 读取块、零基地址和 16-bit 无符号值边界；不实现协议解析，可与 #2 并行。
3. **#4 RS485 Modbus RTU 单设备持续采集与原始寄存器当前状态**：依赖 #2、#3。
4. **#5 同一路 RS485 多设备串行轮询与故障隔离**：依赖 #4。
5. **#6 设备当前状态 API 与 React 实时寄存器页面**：基础页面可在 #4 后开始，完整通信状态依赖 #5。
6. **#7 第一阶段端到端验收与稳定性收口**：依赖 #2～#6。

```text
#2 配置与读取块 ─────┐
                     ├─→ #4 原始寄存器采集 ─→ #5 多设备/故障隔离 ─┐
#3 原始读取契约 ─────┘                                             ├─→ #7 阶段验收
                               └────────────→ #6 API / 页面 ───────┘
```

各 Ticket 不得引入设备协议解析、MQTT、告警、控制、Modbus Server、TCP/UDP、高开保护器或实时历史数据库。现有 GitHub Issue 标题和正文如仍描述协议解析，需要在实施前按 ADR-0014 单独重定范围。

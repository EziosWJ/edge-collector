# 第一阶段 Ticket 拆分

> 总 Spec：Issue #1
>
> ADR：ADR-0011
>
> 技术方案：`docs/design/phase-1-acquisition-technical-design.md`

第一阶段按纵向能力拆分，避免按“数据库 / 后端 / 前端”横向切割成无法独立验收的碎片。

## 实施顺序

1. **#2 采集配置基础**：RS485 通道与设备配置持久化、CRUD、页面配置。
2. **#3 馈电保护器协议契约与解析**：把现有协议资料固化为可测试的解析规则；可与 #2 并行。
3. **#4 RS485 Modbus RTU 单设备持续采集与内存当前状态**：依赖 #2、#3。
4. **#5 同一路 RS485 多设备串行轮询与故障隔离**：依赖 #4。
5. **#6 设备当前状态 API 与 React 实时数据页面**：基础页面可在 #4 后开始，完整通信状态依赖 #5。
6. **#7 第一阶段端到端验收与稳定性收口**：依赖 #2～#6。

```text
#2 配置基础 ─────┐
                 ├─→ #4 单设备采集 ─→ #5 多设备/故障隔离 ─┐
#3 协议解析 ─────┘                                         ├─→ #7 阶段验收
                           └────────────→ #6 API / 页面 ────┘
```

各 Ticket 不得引入 MQTT、告警、控制、Modbus Server、TCP/UDP、高开保护器或实时历史数据库。

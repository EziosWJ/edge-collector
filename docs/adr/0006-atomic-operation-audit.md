# ADR-0006: 业务写入与操作审计日志原子提交

## Status

Accepted

## Context

操作审计日志是管理模块成功写操作的业务记录。原实现将业务写入与审计写入分成独立数据库操作：审计失败时，业务数据已变更但调用方收到失败；审计类型和持久化实现还由 RBAC 模块承载，已被多个非权限模块依赖。

## Decision

操作审计能力归属 `internal/audit`，而不是 RBAC、日志管理或 platform。它拥有操作审计日志的事件、记录 interface 与数据库 adapter；日志管理保留登录日志和操作审计日志的查询、详情与清空功能。

每个会写操作审计日志的业务 Repository 在内部使用同一所选数据库 transaction 完成业务写入和审计写入。Service 只提供业务规则与审计事件，不依赖 GORM 或事务 callback。任一写入失败，整次操作回滚；SQLite 忙等待耗尽时由 HTTP 层统一返回 503，事务不自动重放。

批量删除和批量状态变更以整次请求为原子范围，并写一条批量操作审计日志。批量上传保留逐文件成功/失败结果；每个成功文件自身的元数据写入和审计日志原子提交。文件系统写入不参加数据库 transaction，数据库失败后由文件模块同步尽力补偿删除新写入的物理文件；补偿失败记录应用日志，允许暂时留下孤儿文件，不预建清理队列或后台 worker。

## Consequences

- 调用方的成功结果同时代表业务数据和操作审计日志均已提交。
- 业务模块不再以 RBAC 类型表达操作审计。
- Repository 的写操作 interface 会显式接受操作审计事件；只有出现真实的跨 Repository 原子用例时，才重新评估更通用的事务 seam。

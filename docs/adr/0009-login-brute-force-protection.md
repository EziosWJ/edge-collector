# 登录防爆破与失败写入放大控制

Status: accepted

登录接口采用 Go API 进程内的登录尝试准入防护，按可信客户端 IP 和规范化用户名分别限制登录尝试，并在凭据查询、BCrypt 校验和失败登录日志写入之前拦截超限请求。真正进入凭据核验但失败的结果继续写入 `sys_login_log`；登录防护拦截不写数据库，改由指标和受控应用日志观测。第一版不引入 Redis、网关限流或持久化账号锁定，因此重启、实例切换和多副本部署会丢失或绕过部分防护状态。

## Decision

- 登录防护只作用于结构合法的密码登录请求。IP 和用户名维度在凭据核验前原子消耗准入额度；未知用户、禁用用户和密码错误都计入尝试额度。
- IP 维度和用户名维度独立生效，任一维度达到边界即返回 `429` 和 `Retry-After`。退避通过拒绝请求表达，不让服务端睡眠占用 worker。
- 默认窗口为 10 分钟；IP 最多 20 次、用户名最多 5 次登录尝试。连续失败退避为 1、2、4、8 秒，最高 30 秒；临时锁定为 10 分钟。
- 成功登录清除该用户名的失败、退避和临时锁定状态，但不清除 IP 维度状态。
- 用户名限流键只做首尾空白清理并保留大小写；内部状态键使用不可逆摘要。未知用户执行固定 BCrypt dummy 校验，以减少耗时差异。
- 状态仅保存在进程内存中，按过期时间清理并设置最大条目数；达到容量时淘汰最旧状态，用户名维度允许降级，由 IP 维度继续提供保护。
- 认证错误继续保持现有响应体结构。429 使用 HTTP 状态码和响应 `code` 429，消息不说明具体命中的维度；第一版不需要前端倒计时或其他 UI 改动。
- IP 来源默认使用直接连接地址；只有显式配置可信代理网段时才使用转发头中的客户端 IP。
- 登录防护阈值从配置读取；任一维度的阈值配置为 `0` 即关闭该维度，两个维度均为 `0` 时关闭整个登录防护。关闭防护时应通过启动日志或指标明确暴露该状态。

## Consequences

- 重复攻击在数据库用户查询、BCrypt 和失败登录日志写入之前被截断，显著降低数据库写放大和密码校验 CPU 消耗。
- 登录日志继续表示凭据核验结果，不包含被防护拦截的每次请求；运维需要通过指标观察拦截量和误伤。
- 进程内状态不具备跨副本一致性，也不具备重启后持续性；正式多副本或高风险部署仍需要在网关或共享限流存储补充防护。
- 配置为 `0` 便于开发和故障绕行，但可能让生产实例无保护启动，因此关闭状态必须可观测。

## Considered Options

- 持久化账号锁定：未采用。它需要额外的数据库写入和状态字段，并可能被攻击者利用来锁定合法账号。
- Redis 或网关级共享限流：暂不采用。当前项目明确不提前引入分布式基础设施；达到多副本或高并发条件时重新评估。
- 服务端睡眠实现指数退避：未采用。它会把攻击流量转化为被占用的 HTTP worker。

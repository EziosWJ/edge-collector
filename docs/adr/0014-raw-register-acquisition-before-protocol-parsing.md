# ADR-0014: 第一阶段先采集原始寄存器，暂缓设备协议解析

## Status

Accepted

## Context

第一阶段当前实现已经把固定地址 `0～6` 解释为电压、电流、功率等业务值，但仓库没有可用于实机验收的厂家寄存器表，该映射只是开发闭环样例。继续把样例换算结果作为实时业务数据，会让页面和 API 表现出尚未被协议事实支持的语义。

本 ADR supersede ADR-0011 中“第一阶段内置馈电保护器协议解析”的决定，以及 ADR-0013 中“两段固定电气量 / 状态读取”的设备采集假设。ADR-0011 的 RS485 Modbus RTU、内存当前状态、多设备故障隔离和阶段非目标继续有效；ADR-0013 的通道请求节流和配置运行时刷新继续有效。

## Decision

### 1. 第一阶段输出原始寄存器数据

第一阶段的采集结果是 Modbus 传输校验后得到的 16-bit 无符号寄存器值，不是完整 RTU 报文字节，也不解释为有符号数、浮点数、多寄存器组合、比例、单位或状态位。`FEED_PROTECTOR` 继续表示设备业务类型，但不参与本阶段的寄存器读取和解析分派。

### 2. 每台设备配置寄存器读取块

设备可以维护多个有序读取块，每个读取块持久化 ID、设备 ID、同设备内唯一的名称、功能码、零基起始地址、寄存器数量和排序号。第一阶段只支持 FC03 Holding Registers 和 FC04 Input Registers；单块数量为 `1～125`，地址范围不得超过 `0～65535`，同一设备和同一功能码下的读取块不得重叠。

读取块没有独立启用状态，不需要时直接删除。它只描述读取范围，不允许配置业务字段、数据类型、字节序、word order、倍率、单位或状态位语义。

读取块随设备配置写入成功后热刷新。只修改名称或排序时保留已有快照；修改功能码、起始地址或数量时丢弃旧快照，并以空值等待新范围首次读取。刷新必须等待当前设备采集结束，不中断正在执行的 Modbus 请求。

### 3. 当前状态按读取块保存

`/api/v1/acquisition/states` 继续表达启用设备的进程内当前状态，数据部分改为 `registerBlocks`。首次成功前也按配置展示寄存器地址，值为空；一次读取块成功时，该块全部寄存器作为同一批次更新；失败时保留上次成功值，但整块标记为本轮无效，并保留最近尝试时间、最后成功时间和最近错误。当前状态不保存历史批次。

设备所有读取块成功时为 `ONLINE`；部分成功、部分失败时为 `DEGRADED`；只有所有读取块连续失败达到设备阈值时才为 `OFFLINE`，任一读取块成功都会中断“全部失败”连续计数。

### 4. 页面作为实时寄存器观察器

前端页面名称改为“实时寄存器”，只列出已启用且已加载到采集运行时的设备。详情按读取块展示名称、功能码、零基十进制地址、当前值、本轮有效性和最后成功时间，并展示读取块最近尝试时间与错误。

寄存器值默认以四位 HEX 展示，可在页面级全局切换为无符号 DEC 或 16 位 BIN；切换只改变文本表示，不改变 API 数值和寄存器地址。现有电压、电流、功率、单位和倍率等占位业务字段退出第一阶段主链路。

## Considered Options

- **继续保留占位解析，只在页面隐藏**：API 和内存仍会传播未经厂家协议确认的业务语义，因此不选。
- **展示完整 RTU HEX 帧**：需要在传输层增加收发帧捕获，目标偏向通信抓包而不是寄存器观察，因此不进入第一阶段。
- **页面临时发起手工读取**：会让 HTTP 请求直接驱动串口事务，并绕开持续采集和当前状态模型，因此不选。
- **支持通用协议映射配置**：有符号数、浮点数、字节序、倍率和状态位会使本阶段重新进入协议解析，因此推迟到厂家协议确认后的独立设计。

## Consequences

- 第一阶段可以先验证真实设备通信、地址范围、调度、部分失败和页面观察，而不声称已经理解设备业务语义。
- 需要为 PostgreSQL 和 SQLite 增加读取块配置，并同步修改运行时、当前状态 API、前端类型、页面和测试。
- 当前固定馈电保护器解析器及其工程值测试退出主链路；厂家协议确认后，业务解析应消费原始寄存器快照，并形成独立的业务实时数据模型。

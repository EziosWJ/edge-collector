# ADR-0007: 站内通知与触发操作原子提交

状态：Accepted（设计已确认，尚未实施）

首版站内通知用于管理员手动发布及用户角色分配变更。已选择角色变更、对应操作审计与通知在同一数据库事务中提交，任何写入失败均回滚并提示重试；手动群发的通知、接收记录及操作审计同样整次提交或回滚，以保证成功响应代表接收人已有可查询的通知。

该决策延续 [ADR-0006](0006-atomic-operation-audit.md) 的业务与审计原子性，新增通知与角色分配之间的事务边界。数据库事务留在持久化边界，Service 不依赖 GORM；不采用“业务先成功、通知异步补发”，避免首版引入补发队列及其一致性维护成本。

代价是通知写入故障会阻止角色变更，群发事务的开销也随接收人数增长。未来若实际发送规模使同步事务无法满足响应要求，或业务要求通知故障不阻断角色变更，再重新评估事务发件箱与异步投递。

# 站内通知设计

状态：首版已实现。

## 已确认需求

- 首版同时支持管理员手动发布和业务自动触发。
- 接收范围支持全体用户和指定用户。
- 全体用户按发布时已有且启用的账号确定；发布后新建账号不补收历史通知。
- 首个业务自动触发场景为角色变更，通知受影响用户。
- 接受约 30 秒刷新延迟；页面打开时加载，页面可见时每 30 秒刷新未读数。
- 用户角色分配操作中，角色集合实际变化且保存成功后才发送通知，展示变更前后角色；包括首次分配、调整和清空角色，重复保存相同角色不发送。新建账号本身不触发通知。
- 管理员填写标题和纯文本正文，确认后立即发布；首版不提供草稿或富文本。
- 发布后内容固定，不可修改或撤回；错误内容通过新发布的更正通知处理。
- 顶部铃铛显示未读数和最近通知预览，另提供“我的通知”分页列表。
- 打开通知详情才标记已读，支持全部已读；首版不提供个人删除。
- 手动发布和管理仅允许拥有启用的 ADMIN 角色的用户执行，可查看手动发布记录和汇总已读人数；普通用户只能查看和标记自己的通知。服务端独立执行授权校验。
- 角色变更、操作审计和通知在同一数据库事务提交，任一步失败全部回滚并提示重试；手动群发也整次成功或整次失败。
- 历史通知持续保留，首版不自动清理，通过分页查询。
- 指定用户仅可选择启用账号；提交时若任一选中账号已禁用或删除，整次发布失败并提示重新选择。
- 已收到的通知在账号禁用后保留，重新启用后可查看；不补收禁用期间的全体通知。
- 停用角色、删除角色或修改角色菜单权限暂不触发通知。

## 实施范围

- 后端新增站内通知模块、数据库 migration、通知查询与已读接口、管理员发布与记录查询接口，补齐 Swagger。
- 业务自动触发先接入现有用户角色分配用例；事务一致性决策见 [ADR-0007](adr/0007-atomic-site-notifications.md)。
- 前端新增顶部通知入口、“我的通知”页面和管理员通知管理页面，按既有导航与权限展示方式接入。
- 使用现有数据库和 REST API，按已确认的刷新周期轮询。

## 验收标准

1. ADMIN 可向全体启用用户或指定启用用户发布标题与纯文本通知，并查看发布记录、接收人数及汇总已读人数。
2. 全体通知的接收范围固定为发布时的启用账号；新建账号和发布时禁用的账号不能读取该历史通知。
3. 指定接收人失效时发布整体失败，无部分送达；数据库写入失败时通知、接收记录与对应操作审计全部回滚。
4. 用户角色首次分配、调整或清空时，仅在集合实际变化后产生一条包含前后角色的通知；相同集合即使顺序不同或包含重复输入也不额外通知。
5. 角色变更通知或审计写入失败时，角色关联同步回滚；新建账号、修改角色定义与角色菜单权限不触发通知。
6. 非 ADMIN 无法调用通知管理接口；任一用户无法通过其他用户的通知标识读取内容或修改其已读状态。
7. 铃铛和个人通知列表展示本人通知；查看预览不算已读，打开详情或执行全部已读后更新未读数；重复标记不重复累计已读人数。
8. 页面打开时加载，页面可见时每 30 秒刷新未读数；退出登录或离开相关组件时清理轮询。
9. 已发布内容不可编辑或撤回；用户无删除功能，历史通知不自动清理。
10. 账号禁用后历史通知保留，重新启用后可以继续查看，禁用期间的全体通知不会补发。

## 实现前需验证的现状

- 已定向核查：前端顶部目前没有站内通知入口；后端目前没有通知模块或通知路由。
- 项目已有角色管理、操作审计和数据库会话认证，可作为后续设计的接入基础。
- 用户角色分配已有事务内审计，但目前重复保存也会重写关联；实际变化通知需要补充前后角色集合比较。
- 当前用户查询返回动态角色编码，可用于通知模块授权；现有认证中间件本身不执行 ADMIN 授权判断。
- 已实现后端通知模块、数据库迁移、角色变更触发、个人通知中心和 ADMIN 管理页面。

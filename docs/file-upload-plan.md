# 文件上传需求讨论

## 已确认

- 前端在后台同一演示页提供单文件、多文件、图片三个独立示例，连接真实后端接口。
- 示例展示上传状态、结果和错误；图片支持预览。
- 多文件部分失败时保留成功项，支持重试失败项。
- 匿名上传的业务场景暂未确定。此前讨论的问卷场景及其专属约束已撤回，不作为本轮实现依据。

## 已授权实施方案

- 完成上述三个登录态上传 demo，复用并补齐现有后端上传能力。
- 修复图片预览的鉴权链路，以及批量上传同名文件失败重试的问题。
- 后台通用文件上传维持现有单文件 50 MB 上限；图片上传增加服务端内容校验。
- 匿名接口维持关闭，本轮不实现匿名上传入口或匿名附件业务模型。
- 后端通过 `task backend:check`，前端通过 `task frontend:lint` 和 `task frontend:build`；补充相关行为测试并验证真实上传及预览链路。

## 已确认的上传资源边界

- 单文件内容最多 50 MiB（52,428,800 字节）；批量上传最多 20 个文件，文件内容总量最多 200 MiB（209,715,200 字节）。
- 原始 HTTP body 必须在 multipart 解析前受限：单文件接口最多 55 MiB，批量接口最多 210 MiB；未登记策略的 multipart 接口直接拒绝。
- 单文件和批量上传均采用流式 multipart 解析；`businessModule` 最多 50 个 Unicode 字符且最多 200 字节，`remark` 最多 500 个 Unicode 字符且最多 2,000 字节，文件名最多 255 字节。
- 全局最多 8 个进行中的 multipart 上传；请求头读取超时 10 秒，上传读取时长最多 5 分钟；反向代理限制不得高于应用限制。
- body、文件数或批次总大小超限返回 HTTP 413 / `code=413`；批量中单个文件超限继续保留逐文件失败结果。详见 [ADR-0008](adr/0008-file-upload-resource-bounds.md)。

## 匿名上传：后续业务明确后再决策

- 谁可以取得上传资格，凭证如何签发及失效。
- 文件归属、访问范围，以及是否存在业务提交和绑定过程。
- 允许类型、大小、数量、频率与容量限额。
- 临时附件保留期限、物理删除与清理策略。

不沿用此前问卷方案中的每文件 10 MB、每题 5 个、2 小时链接、24 小时清理或问卷管理者授权规则。

## 实现与验收

- 页面入口：页面示例 → 文件上传 Demo，路由 `/examples/file-upload`。
- 复用 `/api/system/file/upload` 与 `/api/system/file/upload-batch`；批量失败结果增加从 0 开始的输入 `index`，前端按该索引保留失败项，避免同名成功文件重复上传。
- 图片上传支持 PNG、JPEG、GIF，服务端验证完整解码内容，最多 2500 万像素；文件预览与头像通过受信任 API 获取带鉴权的文件流，外部头像不附带登录凭证。
- 补充既有 `SourceSegmentVO` 缺失类型，解除前端构建阻碍。
- `task backend:check`、`task frontend:lint`、`task frontend:build` 均通过；构建仅提示 bundle 超过 500 kB。
- 独立 PostgreSQL 与 SQLite、临时 API 和临时文件目录上的 HTTP 验收通过：普通文件与合法图片上传、鉴权预览、伪装及截断图片拒绝、同名批量失败索引、匿名上传与预览拒绝。
- Chromium 实际交互通过：三个 demo、图片像素加载、清除图片、多文件失败重试与成功记录保留、390px 布局、个人头像、外部头像不携带 Token、原文件管理预览及同名重试。
- 当前环境未安装 `golangci-lint`；已检查改动 Go 文件格式，并通过 `go vet`。
